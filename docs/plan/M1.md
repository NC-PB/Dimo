# M1 Manual ballooning MVP

Goal from [09 Roadmap](../spec/09-roadmap.md): place balloons, characteristic table synced with the
viewport, numbering and renumbering, styles, undo, project save and load, ballooned PDF and CSV and
XLSX export, EN and DE UI.

**Exit criterion:** a real drawing can be ballooned and exported faster than with a PDF editor and a
spreadsheet (owner measures with a drawing of his choice, result recorded in STATUS.md).

Requirements in scope: FR-DOC-05, FR-DOC-07, FR-BAL-01, FR-BAL-02, FR-BAL-03, FR-BAL-06, FR-BAL-09,
FR-BAL-10, FR-BAL-12, FR-CHR-01, FR-CHR-02, FR-CHR-09, FR-EXP-01, FR-EXP-09, FR-EXP-11, FR-SET-04,
NFR-REL-01 to 03, D-21, D-23, D-24, D-27, D-28, D-33, D-51.

Out of scope (later milestones): box select with text, parsing and tolerance derivation (M2),
numbering strategies and sub-numbering (M2), samples and results (M3), proposals and review (M4).

Tasks are grouped in waves. Tasks in one wave can run in parallel. Each task ends with green
`./scripts/check.sh` and a signed commit.

## T1.1 Domain model and command engine (wave 1)

Refs: [07 Data model](../spec/07-data-model.md), [05 Architecture](../spec/05-architecture.md)
principle 1, [rust.md](../dev/rust.md), FR-BAL-09, FR-BAL-10, FR-BAL-12, FR-CHR-01, FR-CHR-02,
FR-CHR-09, FR-DOC-05, FR-DOC-07, NFR-REL-02, D-21, D-23, D-24, D-27

- `dimo-core` types: `Project`, `DrawingRevision` (file name, SHA-256, sheets), `Sheet` (size,
  rotation, kind, unit, scale), `Characteristic` with all M1 fields (kinds from FR-CHR-01, fields
  from FR-CHR-02, exact decimals, limits stored explicitly), `SourceRegion`, `Balloon` (position,
  leader anchor, style override), `BalloonStyle` (circle, flag, rectangle; size, color, leader;
  project default per D-24), `AuditEntry`, `NumberingLock`. ID newtypes (`CharId`, `BalloonId`,
  `SheetId`, `RevisionId`) around UUID. Reuse the shared types from `dimo-core::truth` where they fit.
- Command engine: `Command` enum, apply returns a `Patch`, every command has an inverse, unlimited
  undo and redo, command batches (one undo step for group operations), audit entry per command
  with user name from a provider (D-27). Commands for M1: add characteristic with balloon, update
  fields, move balloon (and leader anchor), delete characteristics, restyle balloons, reorder and
  renumber (placement order, D-21), set sheet rotation, unit and scale, lock and unlock numbering
  (insert policy "next free number" when locked, D-23).
- Numbering: display numbers derived from order, stable IDs never change.
- `schemars` on everything that goes into `project.json`. IPC DTOs derive `specta::Type`.
- Tests: property tests (proptest) that any sequence of commands followed by the same number of
  undos returns the original state, and redo returns the final state. Table tests for renumbering
  and locked inserts.

Acceptance:
- [x] Apply then undo returns the original state for random command sequences
- [x] Renumber and lock rules covered by table driven tests
- [x] No IO in `dimo-core`, dependency direction test green

## T1.2 Ballooned PDF writer (wave 1)

Refs: FR-EXP-01, FR-EXP-11, D-24, D-33, ADR 0005, [06 Tech stack](../spec/06-tech-stack.md)

- `dimo-pdf` API that writes a copy of the original PDF with vector balloons added as page
  content: drawing primitives (circle, flag, rectangle, number text, leader line) in sheet space,
  independent of `dimo-core` domain types. Original content stays vector and unchanged.
- Optional output as PDF annotations instead of page content (D-33 setting).
- Deterministic: same input and balloons give byte identical output (FR-EXP-11). No timestamps or
  random IDs unless they come from the input.
- Font for numbers: a bundled font with a permissive license, embedded and subset, so numbers render
  the same everywhere.

Acceptance:
- [x] Ballooned test_drawing_1 opens in PDFium, original text runs are still extractable
- [x] Two runs produce byte identical files (test)
- [x] Rendered snapshot of a ballooned sheet is stable
