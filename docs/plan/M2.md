# M2 Assisted capture

Goal from [09 Roadmap](../spec/09-roadmap.md): box select with PDF text, callout parser, tolerance
engine (ISO 2768 first, then fits, decimal rules, custom tables), explanations, numbering
strategies.

**Exit criterion:** box select on a vector PDF yields correct limits for 99 percent of common
callouts. "Common callouts" are defined in T2.9; the measurement runs as a test over the corpus and
synthetic drawings, the owner confirms the result on a real drawing of his choice.

Requirements in scope: FR-REC-01, FR-REC-02, FR-REC-08, FR-TOL-01, FR-TOL-02, FR-TOL-04,
FR-TOL-06, FR-TOL-07, FR-TOL-08, FR-TOL-09, FR-BAL-04, FR-BAL-05, FR-BAL-07, FR-BAL-11, FR-CHR-08,
FR-CHR-10, D-20, D-21, D-22, D-23, D-25, D-43, NFR-REC (parser property tests).

Out of scope (later milestones): auto detection, title block reading, zone and view detection,
token grouping across a whole sheet, confidence calibration, review queue (M4); OCR (M5); feature
control frames, general geometric tolerances (ISO 2768-2), ISO 13920 and ISO 9013, flag notes,
variable tables (M6); samples and reports (M3).

Tasks are grouped in waves. Tasks in one wave can run in parallel. Each task ends with green
`./scripts/check.sh` and a signed commit.

## Decisions taken in this plan

The spec leaves these open. They are the simplest options consistent with it and are entered in
the STATUS decision log. Decisions 1 to 4 confirmed by the owner on 2026-10-10. **Owner: confirm 5 and 6.**

1. **Zones and views are defined by hand in M2.** D-21 makes "sheet, then zone" the default from
   M2, but zone detection (FR-DOC-06) and view detection are M4. M2 adds a manual zone grid per
   sheet (rows, columns, labels, frame rectangle) and user drawn view rectangles. Without a grid,
   "sheet then zone" falls back to reading order on the sheet.
2. **The general tolerance is a project setting in M2.** Reading it from the title block
   (FR-DOC-08) is M4. The project stores the general standard and class (for example ISO 2768-m),
   decimal place rules and unit rounding; new projects start with none, so untoleranced
   dimensions get "no tolerance defined" (spec 08 stage 7) until the user sets one.
3. **Derivations are stored structured, explanations are rendered.** The project stores the rule
   and its parameters (table id and version, size range, class, fit); the explanation text is
   built from that in the UI language. Exports write the rule in a stable English form.
4. **Custom tables travel with the project.** A custom table used by a project is copied into the
   container (`tolerances/<id>.toml`), so a project opens with the same limits on another machine.
   Shipped tables are referenced by id and version.
5. **Typed values go through the same parser.** Text typed into the value field during manual
   capture (FR-BAL-02) is parsed and interpreted like a box selection. Unparseable text stays as
   requirement text with no limits, as today.
6. **Basic dimensions** are recognized in M2 only when the box selection contains a closed
   rectangle tightly around the text (vector paths). Otherwise the user marks them. Reference
   dimensions are recognized from parentheses.

## T2.1 Callout parser (wave 1)

Refs: [08](../spec/08-recognition-pipeline.md) stages 5 and 6, FR-REC-08, FR-CHR-08, D-20, D-25,
[06](../spec/06-tech-stack.md) (winnow, proptest), [testing.md](../dev/testing.md)

- `dimo-notation`: `parse_callout(&str) -> Result<Callout, ParseError>` with winnow. `Callout`
  holds kind prefix (`Ø`, `⌀`, `DIA`, `R`, `SR`, `SØ`, `M` thread, angle), quantity (`4X`, `4x`,
  `4 ×`, `2 PL`), nominal, tolerance, fit, suffix (`THRU`, depth), reference and basic markers,
  unit. All numbers `rust_decimal`.
- Tolerance forms: `±0.1`, `+0.1 -0.05` and `+0.1/-0.05` (stacked lines joined by the caller),
  one sided `+0.1 0` and `+0 -0.6`, limit dimensions `12.02/11.98` and `12.02-11.98` written as
  two lines, `MIN` and `MAX`, fit `H7`, `g6`, `H7/g6`, fit with printed deviations
  (`Ø8 f7 -0.0127 -0.0279`).
- Kinds: linear, diameter, radius, spherical radius and diameter, angle (decimal degrees and
  `30°15'`), chamfer (`1x45°`, `C1`), metric thread (`M8`, `M8x1.25`, `M8x1.25-6H`), reference
  `(42)`, depth.
- Number formats: decimal point and comma, hyphen and U+2212 minus, leading zero optional, inch
  values (`.250`, `1/4`, `1 1/4`, `"` and `in`) parsed and marked inch (D-20).
- `ParseError` carries the byte position and what was expected. No panics on any input.
- Printer `Callout::to_canonical()`; proptest: generated callouts print and parse back equal, and
  arbitrary strings never panic. Table driven tests for every requirement text in
  `corpus/truth/test_drawing_1.truth.json` and every form listed above.

Acceptance:
- [x] Every corpus truth callout parses to the expected kind, nominal and tolerance parts
- [x] Round trip and no panic property tests pass with at least 10,000 cases each
- [x] Error positions covered by tests

## T2.2 Tolerance table format and ISO 2768-1 (wave 1)

Refs: D-43, FR-TOL-02, FR-TOL-07, `.claude/skills/tolerance-table`, rule 7, [07](../spec/07-data-model.md)

Use the `tolerance-table` skill. All tables stay `status = "draft"`.

- File format (TOML) and Rust types in `dimo-tolerance` with `schemars`; schema published to
  `docs/schema/tolerance-table.schema.json` with a staleness test; `data/tolerances/README.md`.

- `data/tolerances/iso-2768-1.toml`: linear (f, m, c, v), broken edges radius and chamfer,

  duplicate ids refused, every load validated.
- D-43 release gate: a check in `scripts/check.sh` and CI that fails a release build (tag or
  `DIMO_RELEASE=1`) while any shipped table is `draft`; normal builds only warn.
- Add the table to "Waiting for the owner" in STATUS.md with the values to verify.

## T2.3 ISO 286 fit tables (wave 1)

Refs: FR-TOL-04, D-43, T0.10 truth review notes

- `data/tolerances/iso-286.toml`: standard tolerance grades IT01 to IT18 and fundamental
  deviations for holes (A to ZC) and shafts (a to zc) up to 500 mm nominal, including the delta
  values for holes K to ZC. Same format as T2.2. Draft.
- Expansion `limits(fit, nominal) -> (upper_dev, lower_dev)` in `dimo-tolerance`, exact decimals,
  with the special cases of the standard (js and JS, hole rules with delta, sizes exactly on a range
  bound).
- Test vectors for every fit in the corpus truth file and in `tools/synth` `FITS`, plus range
  boundaries for the common fits (H6 to H11, h5 to h11, g6, f7, e8, d9, k6, m6, n6, p6, js and JS).
- `tools/synth` keeps its own `FITS` table (independent truth source); a test reports differences
  between the two instead of sharing code.

- [x] Differences between `FITS` and the table are listed for the owner, none silently resolved

## T2.5 Tolerance engine (wave 2, after T2.1 to T2.4)

Refs: FR-TOL-01, FR-TOL-02, FR-TOL-04, FR-TOL-06, FR-TOL-07, FR-TOL-08, FR-TOL-09,
[08](../spec/08-recognition-pipeline.md) stage 7

- `dimo-tolerance::interpret(&Callout, &ToleranceContext) -> Interpretation` with limits,
  deviations, unit and `ToleranceDerivation`. Precedence FR-TOL-01: explicit, fit, drawing rule
  (custom table assigned in the project), general standard by size range, decimal place rule.
- Explicit deviations always win. If they differ from the fit table, add a hint, never correct.
- No tolerance and no general rule: `no_tolerance_defined`, no limits.
- Angles, radii and chamfers use the matching ISO 2768-1 table parts. Reference and basic
  dimensions get no limits and `inspect = false` (D-25, FR-CHR-08).
- Unit conversion mm and inch with configurable rounding; the derivation records the conversion.
- Loader check (from T2.4): id and version inside a stored custom table must match the project
  settings entry.
- Explanation builder: structured derivation to English and German text, used by the UI and by
  tests. Golden tests (insta) for one explanation per rule.

Acceptance:
- [ ] Every limit in the corpus truth file is reproduced (after the owner's truth review)
- [ ] Table driven tests for each precedence level and each conflict case
- [ ] Explanation snapshots in English and German

## T2.6 Box select with PDF text (wave 2, after T2.1 and T2.4; uses T2.5 when merged)

Refs: FR-REC-01, FR-REC-02, ADR 0006, `.claude/skills/ipc-command`, rule 4

- `dimo-pdf`: text runs and characters inside an oriented box (rotated text included), and closed
  rectangles around a run for basic dimensions (decision 6).
- `dimo-detect::box_select(sheet, region, context) -> Vec<Proposal>`: runs in the box ordered in
  reading direction, stacked tolerances joined (upper above lower), parse, interpret. Parse errors
  become a proposal with raw text, no limits and the error position.
- IPC: `propose_from_region` (job if slow, else direct), `accept_proposals`.
- `Proposal` gains job id and engine versions (spec 07, left out in T2.4).
- Frontend: the box tool (B, drag) shows a proposal card next to the box: requirement text,
  kind, nominal, limits, rule and explanation, editable before accept. Enter accepts, Esc
  discards. The balloon goes where the box tool puts it today.
- Manual capture (decision 5): text typed into the value field is parsed and interpreted through
  the same Rust path.

## T2.7 Numbering strategies (wave 2, after T2.4)
